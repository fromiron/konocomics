정정: confidence 실패에는 전달 스키마와 실제 검증기의 불일치가 있으므로 모델 단독 오류로 분류하지 않는다. 유효 HOLD의 봉인 실패는 조정자의 시험용 명령 선택 오류이며 정상 runner에는 분기가 이미 있다. 코드 변경은 이 문서 갱신에 포함하지 않았다.

## 1. 목표와 변경 범위

앞으로의 Catalog 작업은 다음 구성을 목표로 한다.

| 역할                                   | 담당                |
| -------------------------------------- | ------------------- |
| 일반 작품의 수집·동결 후 판정          | Luna max            |
| 작업 배정·완료 처리·구체적인 예외 해결 | Astra low           |
| 모델 전환 시험의 비교 기준             | 기존 Sol medium     |
| 저장·동결·해시·봉인·발행·readback·백업 | 기존 runner/helpers |

목표는 기존 품질·권한 계약을 유지하면서 작품당 총사용량과 처리 시간을 줄이는 것이다. AA 종합 점수만으로 Luna의 판정 품질이 검증됐다고 간주하지 않는다.

이번 요청은 필요한 최소 운영문서·실행 경로 수정과 신규 작품 3개의 전환 시험을 승인한다. 시험 결과가 아래 조건을 충족하면 신규 일반 작업을 Luna max로 잠정 전환한다. 기존에 승인되지 않은 GitHub push·merge·배포나 새 유료 서비스 사용까지 허용하는 요청은 아니다.

이번 신규 시험 범위에서는 기존 문서의 “Luna는 수집만, 최종 판정은 Sol” 및 “신규 Sol 연속 시험 우선” 배정보다 이 지시를 우선한다. 변경하지 않는 제품·팩터·근거·권한·저장 계약은 그대로 유지한다.

이미 실행 중인 Sol/Luna 작업은 취소하거나 중복 실행하지 않는다. 기존 산출물·동결 입력·모델 및 추론 수준 기록은 소급 변경하지 않는다.

## 3. 일반 작품의 처리 흐름

작품 하나는 다음 순서로 처리한다.

Luna max 수집
→ 원문·관찰 저장
→ COLLECTION_READY
→ Astra가 기존 도구로 저장·백업·동결
→ 같은 Luna max 작업자가 동결 입력으로 판정
→ 판정 산출물 저장·완료 통지
→ Astra가 기존 도구로 직렬 봉인·발행·readback·백업
→ 완료 확인 후 다음 작품 배정

수집부터 동결 후 판정까지 담당 작업자를 유지한다. 동결을 기다리는 작업자에게 다른 작품을 배정하지 않는다.

### Luna의 수집 책임

현재 작품·판본에 맞는 자료를 선택하고 실제로 읽으며, 원문·출처별 관찰·반대 근거·불확실성을 보존한다. 원문은 실제 도구 반환값에서 기존 collector helper로 저장하고 모델이 다시 타이핑하거나 요약으로 대체하지 않는다.

기존 유효 research·최신 HOLD·미소비 관찰을 확인해 중복 수집을 피한다. 일반 근거가 충분하면 멈추고, 추가 수집은 구체적인 gap을 해결할 때만 한다.

동결 전에는 최종 수치 판정이나 승격 결정을 만들지 않는다.

### Luna의 판정 책임

동결 입력과 명시적으로 결속된 prior만 사용한다. 같은 채팅에서 읽었더라도 동결에 포함되지 않은 관찰은 판정 근거가 아니다.

출처의 용도·작품 동일성·안전성·추천 맥락·팩터를 현재 계약과 출력 스키마에 따라 판정한다. 결속되지 않은 유효 근거가 필요하면 입력 보완 필요성을 반환하고, 기억만으로 판정을 완료하지 않는다.

작업자는 공유 DB를 직접 갱신하거나 자체 발행하지 않는다. 판정 파일 저장과 완료 통지의 성공을 확인한다. HOLD·실패도 완료 상태로 통지하며, 알림 전송 실패 때문에 판정 자체를 다시 실행하지 않는다.

### Astra의 정상 처리 책임

배정 workId·작업자·경로·SHA와 실제 도구 반환값을 확인하고 기존 명령을 실행한다.

정상 결과의 원문·관찰·팩터 원장을 전부 다시 읽거나 독립적으로 재판정하지 않는다. 해시·구조 검사 통과를 의미적 정확성의 증명으로 보고하지도 않는다.

같은 입력의 정상 완료 결과는 재사용한다. 중복 완료 메시지는 기존 완료 기록과 해시로 식별하며, 중복 발행하지 않는다.

## 4. 변경하지 않는 판정·권한 계약

whole_work 기준과 현행 팩터 사전을 유지한다.

근거 없음은 unknown이지 0이 아니다. 명시적인 낮은 앵커는 인정하되, 낮은 값에 높은 값의 반복성·장기성·강도를 추가로 요구하지 않는다.

Narrative known ≥4/6, Tone known ≥5/7, Genre·Theme 각각 ≥1의 현행 기준을 유지한다. 전권 독해·초반 1~3권·출처 최소 개수·선택적 Art를 새 승격 조건으로 추가하지 않는다. 신규 Art는 유보하고 accepted prior Art는 보존한다.

작품·판본·매체 동일성, 실제 관측 범위, 출처별 허용 용도, 안전성, prior와 정정 lineage, 입력 digest, Gold와 비대상 데이터 보호를 그대로 유지한다.

원시 모델 출력은 저장됐다는 이유만으로 권한을 얻지 않는다. 신규 판정은 기존 authorizedEvidencePanel 계약과 필수 검증을 통과한 별도 산출물로만 처리한다. reviewedByHuman=false를 유지한다.

Luna와 Sol의 의견 차이 자체는 진단 정보다. 모델 수·다수결·일치율로 accepted, HOLD, manualReview 또는 승격을 결정하지 않는다.

## 5. 신규 작품 3개의 일회성 전환 시험

현재 아직 추천 가능이 아닌 신규 작업 중 실제 수집 가능성이 있는 3개를 선정한다. 쉬운 작품만 골라 결과를 일반화하지 않으며, 선정 시 예상한 난도와 주요 위험을 짧게 남긴다.

이미 승격된 작품, 변경 없는 HOLD, 과거 동결 bundle을 시험 수를 채우기 위해 재처리하지 않는다. 준비된 기존 작업과 진행 중 작업은 별도로 보존·소비한다.

각 시험 작품은 Luna max가 수집하고, 조정자가 동결한 동일한 입력에 대해 Luna max와 기존 Sol medium이 각각 한 번 판정한다. Sol에는 Luna의 판정값이나 평가 내용을 보여주지 않는다.

이 중복 판정은 모델 전환 시험 3개에만 허용한다. 일반 처리의 상시 이중 판정 규칙으로 만들지 않는다.

두 결과는 별도 경로와 실행 기록으로 보존한다. 비교용 Sol 결과는 비발행 산출물이며, 같은 작품을 양쪽 결과로 두 번 발행하지 않는다. Luna 시험 결과도 시험 검토 전에는 발행하지 않는다.

Astra는 불일치한 쟁점과, 일치한 결과 중 2개 작품의 일부 핵심 claim을 실제 원문·팩터 사전에 대조한다. Sol을 정답으로 취급하지 않고, 각 판정이 근거와 계약에 맞는지 확인한다. 전체 원장을 세 번째로 다시 작성하지 않는다.

확인할 핵심 오류는 다음이다.

- 근거 없는 accepted, 잘못된 0, 작품·매체·판본 혼동, 안전성 오판.
- 낮은 앵커를 과도하게 엄격히 해석한 불필요한 HOLD.
- 반복되는 형식 실패·수정·재시도로 인한 실질 비용 증가.

불일치 그 자체를 품질 실패로 계산하지 않는다. 확인된 오류의 종류와 영향 범위를 기록한다.

수집 품질은 두 판정의 일치만으로 검증되지 않는다. 원문과 Luna의 관찰 사이에 중요한 누락·왜곡이 있는지도 위 제한된 검토에서 확인한다. 다른 작품을 수집한 기존 Sol 연속 시험과의 비교는 작품 난도가 통제되지 않았다는 한계를 명시한다.

## 6. 총사용량과 처리 시간 측정

기존 usage·실행 receipt를 이용해 수집 시작부터 최종 후처리까지 기록한다. 별도 장문 보고서나 대시보드를 만들지 않는다.

작품별로 확인 가능한 실제 모델·추론 수준, 호출 수, 비캐시/캐시 입력, 출력·추론 토큰, 경과시간, HOLD·실패 사유, 수정·재시도와 Astra의 처리 사용량을 남긴다.

서로 중복되는 usage 필드는 합산하지 않는다. 조정자 사용량을 작품별로 정확히 배분하기 어렵다면 시험 전체의 조정 비용으로 별도 기록하고, 작품별 수치를 만들어내지 않는다.

다음을 구분해서 보고한다.

일반 처리 비용:
Luna 수집 + Luna 판정 + 정상 조정·후처리 + 실제 수정·재시도.

시험 추가 비용:
비교용 Sol 판정 + 전환 검토 + 구현·진단 비용.

시험 추가 비용을 숨기지 않되, 상시 운영 비용인 것처럼 섞지도 않는다. 캐시히트율이나 worker 토큰만으로 전체 절감을 주장하지 않는다.

AA의 작업당 달러 비용을 Codex 구독 한도 소모량으로 직접 환산하지 않는다. 확인 가능한 사용량과 시간으로 비교하고, 확인 불가능한 비용은 미확인으로 남긴다.

## 7. 예외 처리와 컨텍스트 절약

Astra low는 정상 작업의 전수 검수자가 아니다. 정확한 동일성 충돌, 상충하는 근거, prior 정정, 구체적인 기준 해석 문제만 해당 원문과 계약 범위를 읽어 해결한다.

low로 해결되지 않는 구체적인 쟁점에만 medium 상향을 사용하고 이유와 추가 사용량을 기록한다. 모든 작품을 medium 이상으로 재검토하지 않는다.

근거 자체가 부족한 HOLD는 상위 모델을 호출할 이유가 아니다. 새 관찰·접근 변화·확인된 판단 오류가 없으면 재판정하지 않는다.

순수 형식 오류는 원본·실패본·수정 diff를 보존하고 같은 동결에서 최소 보정 후 재개한다. 새 의미 판단이나 근거 변경이 필요하면 형식 수정으로 위장하지 말고 해당 판정·입력 변경 절차를 따른다.

작업자에게는 해당 작품의 ID·정체/ISBN·필요한 gap·research/prior/HOLD 경로·출력 경로·현재 계약을 전달한다. 전체 대화나 전체 STATE를 복제하지 않는다. 필요한 반대 근거와 관련 prior는 생략하지 않는다.

정상 인계는 상태·workId·경로·SHA·구체적인 gap/오류 중심으로 한다. 원문과 판정 전문을 조정자 채팅에 반복 출력하지 않는다.

완료 큐를 사용하고, 주기적인 “진행 상황?” 모델 호출·캐시 워밍업·중복 준비 보고서를 추가하지 않는다. 공유 저장·발행·STATE 갱신은 직렬로 유지한다.

## 8. 종료 조건과 후속 운영

3개 시험에서 확인된 중대한 품질 저하가 없고, 수정·조정 비용까지 포함한 총사용량 이점이 관측되면 Luna max를 신규 일반 작업의 잠정 기본값으로 전환한다. 이 조건을 충족한 범위에서 같은 전환 승인을 다시 요청하지 않는다.

이때 Sol 비교 호출은 종료한다. Astra의 상시 전수 재검토도 추가하지 않는다. 시험을 통과한 Luna 산출물은 기존 필수 봉인·발행·readback·저장 경로로만 처리한다.

중대한 오류가 확인되면 해당 작품의 발행과 자동 확대를 보류하고 구체적인 원인을 보고한다. 기준을 느슨하게 바꾸거나 같은 입력을 반복 판정해 통과 결과를 고르지 않는다.

품질·비용 비교가 불명확하면 시험을 자동으로 계속 늘리지 말고, 확인된 결과와 부족한 정보·필요한 다음 결정을 보고한다. 3개 시험만으로 일반 오류율이나 품질 동등성이 입증됐다고 주장하지 않는다.

수집만 xhigh로 낮추는 최적화는 별도 후속 후보로 남긴다. 이번 시험에서는 수집과 판정을 모두 Luna max로 유지한다.

완료 보고에는 변경 파일·실제 모델 설정, 수행한 검증, 작품별 결과, 확인된 오류와 처리, 일반 처리/시험 추가 사용량, 신규 기본값 전환 여부를 담는다. 미측정·미검증 사항은 구분한다.

계획서만 작성하고 종료하지 말고, 이 범위의 최소 변경·영향받는 검증·시험을 수행한다. 실행 불가능한 모델이나 접근 권한 문제는 실제 오류와 함께 보고하되, 독립적으로 완료할 수 있는 작업은 계속한다.
