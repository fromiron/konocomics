## 실행 스킬과 통지 감지 — 2026-09-17

- [조정자 스킬](../../.agents/skills/catalog-coordinator/SKILL.md)과 [작업자 스킬](../../.agents/skills/catalog-worker/SKILL.md)은 현재 단계의 지시·기존 도구·관련 문서를 연결한다. 부모는 배정 메시지에서 작업자 스킬을 명시한다. 스킬 추가만으로 캐시·사용량 절감을 주장하지 않는다.

## 현재 Luna 수집·판정 실행 경로 — 사용자 지정 채팅만 사용

### Luna 수집·판정 연속 운영 — 2026-09-19

신규 작품은 고정 Luna max 채팅이 수집과 동결 후 판정을 연속 담당한다. 이미 배정된 작업의 원문·결과를 보존·소비하고 중복 수집하지 않는다. 별도 보조 역할이나 추가 작업방을 임의 생성하지 않는다.

- Luna는 판정에 필요한 자료를 직접 선택·독해하고 기존 collector helper로 원문·관찰·출판사 receipt를 저장한다. 동결 전 수치 판정이나 승격 권한을 만들지 않는다. Art는 계속 유보하며 유효 관찰과 불확실성을 모두 보존한다.
- 수집 후 부모에 `COLLECTION_READY`(workId·researchPath·SHA)를 보내고 전송 성공을 확인한다. 조정자가 저장·백업·동결한 뒤 **같은 Luna 작업방**에 동결 입력과 판정 출력 경로를 전달한다. 이 대기 중 해당 방을 다른 작품에 배정하지 않는다.
- 판정은 동결 입력만 사용한다. 채팅 기억이나 동결 밖 조사 내용을 근거로 쓰지 않는다. 완료 후 기존 `SOL_COMPLETE` → 조정자 직렬 봉인·발행·readback·백업 경로를 유지한다. 변경 없는 HOLD 재판정은 하지 않는다.
- 과거 첫 시험 배정은 `COLLECTION-DISPATCH-SOL-PILOT-001.json`에 보존돼 있다. 이 기록은 추가 비교 호출 지시가 아니다. 수집 시작부터 후처리까지 Luna·조정자의 사용량 차분과 시간, VERIFIED/HOLD 및 사유를 기존 Luna+Sol 결과와 비교한다. 캐시히트만으로 비용 절감을 주장하지 않으며 소규모 비교의 작품 난도 차이를 명시한다.

위 「현재 결정」 표의 **루나1~5 기존 Codex 작업방**을 `gpt-5.6-luna` / `max` 수집·판정 풀로 재사용한다. 판정용 서브에이전트·일회성 `codex exec`·앱 채팅의 CLI `exec resume`로 대체하지 않는다.

### 지정 세션을 확인할 수 없을 때

고정 thread ID의 조회 실패·접근 불가·삭제 등으로 지정 채팅을 확인할 수 없으면 해당 방의 배정을 보류한다. 일시적인 도구 오류인지 확인하되 임의의 다른 채팅·서브에이전트·CLI로 대체하거나 새 채팅을 자동 생성하지 않는다.

사용자에게 확인할 수 없는 방 이름과 ID, 실제 오류를 알리고 **“해당 Luna 작업방을 직접 만들어 ID를 알려주시겠습니까, 아니면 제가 새 Luna max 채팅을 만들어도 될까요?”**라고 명시적으로 묻는다. 사용자 제공 새 ID를 확인하거나 명시적인 생성 허가를 받은 뒤에만 대체 세션을 사용한다. 새로 확인된 ID는 이 문서와 STATE의 판정 풀에 함께 반영한다. 정상 확인된 다른 Luna 작업방의 독립 작업은 계속한다.

### 배정 → 완료 메시지 → 다음 배정

1. 조정자는 현재 채팅 상태와 저장된 배정을 확인하고 **빈 방에만 한 작품**을 배정한다. 최대 다섯 작품을 병렬 판정하며 완료된 방을 재사용한다.
2. `send_message_to_thread`에 해당 thread ID, `model=gpt-5.6-luna`, `thinking=max`을 지정한다. 현재 작품의 동결 입력·스키마·출력 경로와 아래 완료 통지 지시를 함께 전달한다. 조립·동결은 기존 runner/helpers를 사용한다. 신규 방 첫 배정은 시작 통지 또는 실제 도구 실행을 확인한다. 전달됐어도 대기 응답으로 끝났으면 같은 배정을 다시 명시하며 새 작품을 중복 배정하지 않는다.
3. Luna는 현재 동결 입력과 명시적으로 연결된 prior만 근거로 한 번 판정하고 결과 파일을 저장한다. 이전 채팅의 다른 작품 관찰·판정은 근거로 사용하지 않는다. 신규 Art는 유보하며 accepted prior Art는 보존한다.
4. Luna는 결과 저장·SHA 확인 후 `send_message_to_thread`로 부모 채팅 `01a0a3b8-5162-78f0-ac39-4e17f730a70a`에 아래 메시지를 **한 번** 보낸다. HOLD도 완료 통지를 보내고, 결과를 만들지 못하면 `SOL_FAILED`와 실행 경로·실제 오류를 보낸다. 완료 큐 메시지 도구의 성공을 확인한 뒤 최종 답변을 반환한다. 최종 답변만 남기고 종료하지 않는다. 알림 전송이 실패하면 결과 파일을 보존하고 전송 오류를 명시하며, 판정 자체는 재실행하지 않는다.

   통지 이름 `SOL_COMPLETE`·`SOL_FAILED`는 기존 훅/runner 호환용이며 모델명을 뜻하지 않는다.

   `SOL_COMPLETE: workId=<ID>; runRoot=<절대 경로>; decisionsPath=<절대 경로>; sha256=<SHA256>`

5. 조정자는 큐에 도착한 완료 메시지를 후속 작업 신호로 사용한다. 배정된 작품·경로·SHA를 확인하고 기존 runner의 `--decisions`로 직렬 봉인·발행·제품 readback·저장·백업을 수행한 뒤, 준비된 다음 작품을 빈 방에 즉시 배정한다. Luna 판정의 중복 의미 검토는 하지 않는다.
6. 완료 메시지는 승격 권한이나 성공 증명이 아니다. 중복 알림은 기존 `FINISHED.json`과 해시로 식별해 재판정·중복 발행을 하지 않는다. `wait_threads`는 진행 중 첫 완료를 기다리는 보조 수단이며 주기적 모델 호출로 상태를 묻지 않는다.

**「작품 승격 연속 처리」 예약 automation은 삭제됐다.** 타이머 대신 완료 큐 메시지로 이어서 처리한다. 캐시 워밍업 호출은 하지 않으며 세션 누적 usage의 차분으로 작품별 캐시·비캐시 입력과 출력·시간을 기록한다. 캐시히트만으로 총사용량 절감을 단정하지 않는다.

- **형식과 경로는 도구가 처리한다.** 새 결속 전 claim의 evidenceIds/citationUrls 집합은 seal에서 정렬하고 digest를 결속한다. 중복 ID·누락 축·판정값은 자동 보정하지 않으며 prior/correction 또는 이미 digest가 있는 claim은 그대로 검증한다. `seal-result`는 frozen lineage에서 기준 pair를 읽으므로 baseline 인자를 생략한다. `publish`는 현재 pair를 받고 원래 frozen pair를 자동 참조한다. 잘못된 파일 인자는 저장·백업 전에 거부한다.
- **전체 이력을 매번 재수집하지 않는다.** 실행 입력과 직접 lineage bundle을 저장하고, 실제 prior authority/job/recovery 의존은 계속 추적한다. 과거 버전은 append-only 작업 DB에 보존한다. 백업은 두 개의 완전한 SQLite 세대를 유지하면서 새 blob·snapshot만 트랜잭션으로 반영·검증한다. 전체 감사와 복원 검사는 [저장 계약](03-local-authoring-storage.md)을 따른다.
- **판정 기준은 실제 사전에 맞춘다.** whole_work에 초반 3권 조건, 전권 독해, 선택적 Art 정족수를 덧붙이지 않는다. Narrative 4/6·Tone 5/7·Genre/Theme 각 1개, 근거·safety·unknown 의미는 유지한다. 구체적 남은 gap만 수집하고 충분하면 멈춘다. 새 관찰이나 확인된 판단 오류가 없는 HOLD는 재검토하지 않는다.

## 사용자 승인 검토 조정 — 2026-09-13

사용자는 불필요하게 엄격한 검토와 중복 절차를 줄이도록 승인했다. 아래 기존 규칙을 적용할 때 추가 조건을 만들지 않는다.

근거가 충분한 작품은 Sol의 동결 후 판정과 기존 필수 검사를 통과하면 조정자가 바로 승격한다. Oracle 최종 확인은 필수 단계가 아니며, 근거 해석·기준 적용이 애매한 경우에만 해당 쟁점을 상담한다.

실행 가능한 대기 작업이 있으면 완료 메시지를 받은 즉시 다음 담당 작업을 연결한다. 조정자의 직렬 발행·백업 대기 중에도 독립 수집·준비를 진행하며, 통상 Luna 2명/Sol 3명 안에서 대기열에 맞춰 배분한다. 실행 중·완료·후속 배정 대기를 구분해 기록하고 완료된 에이전트를 진행 중으로 보고하지 않는다. 인원 수를 채우려고 동일 HOLD나 완료 검토를 반복하지 않는다.

- 동일 근거·동일 계약의 완료된 의미 검토는 재사용한다. 새 관찰, 구체적 오류·충돌 또는 관련 계약 변경이 있을 때 해당 부분만 검토한다. 기존 도구의 원본 권한·manifest 결속 검사는 유지하되 모델에게 같은 과거 자료를 반복 독해시키지 않는다.
- 실제 판정값의 사전 앵커만 요구한다. 낮은 값에 높은 값의 반복성·강도·장기성·성공을 요구하지 않으며 구체적인 텍스트로 판단할 수 있으면 추가 출처 수·공식 상호보강·직접 본문·전권 독해를 의무화하지 않는다. `remainingGaps`에는 현재 필요한 판단을 막는 부족분만 두고 미독해 권·패널·선택적 축의 한계는 `limitation`으로 구분한다. `pacing`은 사전의 Arc 단위 변화를 평가하며 직접 패널 관찰을 추가 조건으로 삼지 않는다. 근거 집합의 차이를 목표 품질의 열위로 단정하지 않고, 재수집 요청은 판정하지 못한 항목과 필요한 관찰을 지정한다. 기존 승인 팩터의 신뢰성·자격은 범위 변경만으로 낮추지 않는다.
- 부족한 그룹에서 필요한 수만큼의 항목을 보완한다. 대안 축 전부를 조사하거나 한 항목의 보완 때문에 작품 전체 검토를 다시 시작하지 않는다. 충분한 근거가 확보되면 추가 탐색을 끝낸다.
- 서지 혼입·원본 권한 연결·파일 결속 문제는 근거 부족과 구분한다. 기존 정정·복원 경로로 필요한 연결만 해결하고, 해당 문제를 이유로 팩터 재수집을 시키거나 준비된 다른 작품을 대기시키지 않는다.
- Luna Max는 부족한 자료 수집, Sol High는 출처 의미 검토·판정을 맡는다. 조정자는 같은 의미 검토를 반복하지 않고 직렬 발행·최종 결과 확인을 맡는다. 필요한 수치 원장 외 보고는 완료 대상·실제 차단 원인·다음 행동으로 간결하게 남긴다.
- 정확한 작품·출처 연결, 명시적 근거, `unknown ≠ 0`, 필수 coverage, 안전성 및 동결 불변성은 유지한다. 구체적 근거 없는 자동 PASS나 단순 시간 제한에 따른 판정은 하지 않는다.

Luna는 아래 읽기 전용 함수로 실제 수집분을 확인한다. Sol은 수정한 입력의 기존 파서·identity/context/safety 검사에서 실제 실패한 부분과 연결 필드를 확인한다. 실제 freeze가 이 검사를 수행하는 경우 앞에 같은 전체 preflight를 중복 실행하지 않는다. 실패 후에는 원본을 보존하고 새 입력에서 연결 오류를 함께 고친 뒤 재시도한다. 이미 끝난 의미 검토·전체 과거 탐색·무관한 테스트를 다시 수행하지 않는다.

반환 전 구조 검사는 기존 `validate_factor_collection_batch.mjs`의 `validateResearchRow(row, seenWorkIds, true)`를 import하여 DB 쓰기 없이 실행한다. 여러 행에 같은 `Set`을 공유하며 신규 수집의 실제 source audit를 검사한다. CLI 실행·receipt 보존은 조정자의 상위 `run`이 담당한다. Luna는 완결된 원문 산출물을 즉시 전달하며, Sol은 전달된 검사 결과를 재사용한다. 공유 DB 조회 connection·cursor는 조회가 끝나면 닫고 웹 수집이나 모델 검토 중에 읽기 트랜잭션을 유지하지 않는다.

## 기존 실행 규칙 — 2026-09-12 (역할 배정은 2026-09-17 결정으로 대체)

1. **목표와 권한:** 검증 가능한 모든 in-scope 고유 작품을 후보 Catalog의 추천 가능 레벨로 승격한다. 추천 가능 작품 수 확대를 우선하며 Gold 150과 legacy authority를 보존한다. canonical 전환·GitHub 쓰기·배포는 별도 승인 없이는 하지 않는다.
2. **배정:** 활성 서브에이전트는 최대 5명이다. 단순 텍스트 정보 수집은 Luna Max(`gpt-5.6-luna`, reasoning effort `max`), 출처 의미 검토·준비·동결 후 수치 판정은 Sol High가 맡는다. Luna Max는 2026-09-09 사용자 변경 지시 이후 새로 배정하는 작업부터 적용하며, 이전 실행 기록과 동결 산출물의 모델 표기는 소급 변경하지 않는다. Grok·유료 출처는 사용하지 않는다. 서사 근거를 이미지에서 추출하지 않으며 선택적인 Art도 텍스트 근거를 먼저 사용한다.
3. **우선순위:** 발행 가능한 동결 판정 → 준비 완료 → 수집 완료 → 구체적 새 근거가 있는 보류 → 신규 수집 순서다. 같은 단계에서는 남은 필수 근거 부족분과 접근 가능한 자료로 순서를 정한다. ID순 신규 조사나 새로운 근거 없는 보류 재배정을 기본값으로 쓰지 않는다.
4. **Sol의 책임:** 같은 담당자가 최대 5작품의 출처 의미 검토·준비부터 실제 freeze → 동결 후 별도 수치 원장 → seal-result까지 중간 재승인 없이 이어서 맡는다. 실제 동결은 준비된 1~5작품이며 조정자가 고유 batchId·경로·frozen pair를 배정한다. 원시 수집 결과나 준비 완료를 판정 권한으로 대신하지 않는다. 같은 묶음을 여러 Sol에게 중복 검증시키지 않는다. 직접 작성하는 수치 산출물은 구조화 decisions.json 또는 기존 adjudicated-ledger.csv 한 벌이다. 명시적 새 claim·동결 prior 참조·unknown 집합이 완전한 17축과 채택 tag를 구성해야 하며 최종 CSV·결과 파일·digest·manifest는 기존 seal 도구가 생성한다.
5. **조정자의 책임:** Sol의 검토·검사 결과를 채택한다. 동일 출처 재독해, 전체 필드 비교, 동일 검사 재실행, 전체 과거 판정 원장 재검색을 반복하지 않는다. 입력 결속·현재 baseline 충돌·보호 대상 검사는 기존 freeze/seal/publish 경로가 담당하고, 조정자는 직렬 발행과 최종 DB·제품 경로 readback을 맡는다. 동결 판정에 필요한 입력/결과 manifest와 원본 권한 연결은 유지한다.
6. **재검토 조건:** 입력 hash·계약·관련 baseline 상태 변경 또는 구체적 실패·모순이 있을 때 해당 부분만 담당자에게 돌려보낸다. 무관한 작품의 승격만으로 의미 검토를 다시 시작하지 않는다. 과거 판정은 최초 대상별 조회 결과와 원본 권한 경로를 재사용하고 이후 새 관련 artifact만 확인한다. 불완전한 조회를 근거로 과거 판정이 없다고 추정하지 않는다.
7. **실패의 조기 차단:** 맥락 근거 ID가 실제 동일 작품의 출처 행으로 연결되는지 준비 단계에서 검사한다. 기존 DB·동결 packet·supplemental의 지원 경로를 유지한다. 맥락과 안전성은 별도 판정하되 서로 다른 추가 URL을 의무화하지 않는다. 발행기의 최종 무결성 검사는 생략하지 않는다.
8. **묶음 처리:** 완결된 수집분은 1~5작품 단위로 즉시 전달하고 전달 파일에는 이후 append하지 않는다. 다음 반환은 새 파일로 한다. 복잡한 metadata/prior 보류는 준비된 일반 작품과 분리한다. 실패·분할용 고유 ID·경로를 제한적으로 사전 배정할 수 있으며 미사용 ID를 채울 의무는 없다. 이미 동결된 membership은 수정하거나 sealed bundle끼리 합치지 않는다. baseline이 바뀌면 기존 publisher의 frozen/current 충돌 검사를 사용하며 실패를 덮어쓰지 않는다. 0 PASS는 보류 결과로 보존하고 일반 발행 대기열에서 제외한다.
9. **최종 확인:** 실제 후보 SQLite 상태를 읽고 기존 authority·Gold 검사, 단일 catalog build/coverage 확인, 생성된 추천 데이터와 기존 추천 엔진 경로를 확인한 뒤 현재 후보 상태를 갱신한다. 동일 성공 검사를 별도 단계로 반복하지 않으며 추가 검사는 구체적 실패나 변경의 영향을 확인할 때만 한다. candidate 증가와 canonical 증가를 구분한다.
10. **보고 범위:** 필수 기계 필드, 판정, 실제 변경, 실패·남은 근거 부족분, 원본 경로만 남긴다. 이전 근거·계약·해시 목록을 단계별 산문으로 다시 작성하지 않는다. 별도 효율 보고서·대시보드·cache·새 harness를 만들지 않는다. 실패는 즉시 기록하고 실제 처리량을 측정하기 전에는 개선 배수를 주장하지 않는다.
11. **승격 기준:** Genre ≥1, Theme ≥1, Narrative known ≥4/6, Tone/Relationship known ≥5/7을 유지하며 Art는 선택이다. 근거 없음은 `unknown`이며 0으로 채우지 않는다. 기준 검토는 확정 수치와 운영자가 덧붙인 요구를 구분하며, 수치 변경은 품질 영향과 사양 변경을 포함한 별도 제품 결정이다.
12. **추가 조건 금지:** 2점 기준에 4점의 반복·장기성·성공을 요구하지 않는다. 직접 만화 본문/page-level 접근, 출처 3개, 전 3권, 일반 Factor의 독립 정족수를 승격 필수 조건으로 삼지 않는다. 작품 동일성이 확인된 구체적 텍스트 리뷰도 근거다. 초반 1~3권 제한·권수 확인·전권 독해는 요구하지 않는다. 변화는 별도 축이나 필수 조사가 아니며 확보한 리뷰에서 확인할 때만 기존 팩터 근거에 반영한다. 기존 승격 데이터의 신뢰성과 자격은 유지한다. Theme 1은 확인된 에피소드·부소재로 판정할 수 있다. Art의 별도 적격성·독립성 조건은 Art 값을 채택할 때만 적용하며 승격을 지연시키지 않는다.
13. **자료 중심 수집:** 관련 자료 본문을 한 번 읽고 실제 관찰·반대 근거·범위 한계를 함께 남긴다. 같은 자료를 Axis마다 다시 검색하지 않는다. requiredFactOptions와 지정 URL은 탐색 대안이며 전부 조사할 목록이나 HTTP 우선 순서가 아니다. 남은 gap에 맞춰 기존 browser/CUA·문서 도구를 바로 선택할 수 있다. HTTP 셸과 실제 렌더링 결과를 구분하고 같은 셸·공개 종료를 반복 취득하지 않으며, 위 배정의 이미지 서사 제한은 유지한다. 각 source에서 확인한 작성자·관찰을 먼저 기록한 뒤 종합하고 같은 소개는 실제 추가 정보만 남긴다. 기존 객체 writer/관찰을 포함한 단일 draft를 기본으로 하며 외부 메모 조립을 의무화하지 않는다. 짧은 claimCandidates는 구체적 인계에 필요할 때만 남기고 사전 17축 장문 판정을 요구하지 않는다. 같은 관찰을 여러 독립 출처로 부풀리거나 발견한 근거를 숨기지 않는다. 실제 확보한 원문은 기존 provenance 경로로 전달할 수 있으나 새 필수 캡처 게이트나 과거 PASS cache로 삼지 않는다.
14. **Registry 누적:** 검증된 publication pair (C0,R0)에서 R0에 직접 결속한 공통 correction R*를 만들고, 변경되는 모든 Work를 포함한 원래 job·연구 입력을 보존한다. 하나의 호환 request schema로 표현 가능한 수정만 합친다. 독립 job은 같은 (C0,R*)로 동결할 수 있지만 발행은 직렬이며, 첫 실제 publication/readback 후 다음 검증 pair에서만 후속 correction을 시작한다. current/frozen이 다르면 current Catalog·registry는 같은 publication 디렉터리 pair다. registry branch 병합·registry-only 가짜 publication은 하지 않는다.
15. **Prior와 측정 경계:** 대상별 탐색을 재사용해도 참조 bundle의 전체 manifest·원본 claim 결속은 검증한다. 현재 manifest 누락은 FAIL이며 별도 bundle의 완전한 membership·권한 의존 관계를 입증하지 못하면 비관련이나 prior 없음으로 추정하지 않는다. 준비 재고 연결 시험은 신규 처리량에서 제외한다. 신규 처리량은 60분 이상 실제 발행·최종 제품 readback을 마친 고유 신규 eligible 수/전체 경과 시간으로 측정하고 eligible 순증·시작/종료 WIP·실패·수정·대기를 함께 기록한다. 역할 배분별 용량 상한은 그 구성에만 적용하며 목표 미달로 기준을 낮추지 않는다.

현재 수집 형식과 기존 실행 명령은 작업 디렉터리의 `docs/catalog-expansion/factor-collector-instructions.md`와 `AUTHORING.md`에 둔다. 이 절은 운영 방식을 정하며, 해당 문서나 검사 도구가 제품 사양·근거 권한·안전성 계약을 대신하지 않는다.

- 현재 동결 입력과 명시적 prior만 판정 근거다. 이전 작품의 관찰·결론은 대화에 남아 있어도 새 작품의 근거로 채택하지 않는다. 판정 파일을 조정자가 기존 runner의 `--decisions`로 봉인·발행·백업한다.
- 근거 복구 시 provenance 입력 안에 freeze 출력이 위치하면 자기 복사가 발생한다. 출력은 provenance 밖에 두고 freeze 진입 시 차단한다. 실패한 Hachi 준비에서는 모델 호출 전 프로세스를 중단했으며 판정은 생성되지 않았다.
