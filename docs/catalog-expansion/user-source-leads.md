# 사전 수집 리드 규격

현재 확정 사양 · 갱신일: 2026-09-27

이 문서는 `.workspace/user-sources/<workId>.json`의 작성 규격과 자료 채택 기준이다. 리드는 실제 원문을 찾는 안내이며 판정·동결·발행 권한이 아니다. 수집 실행과 원문 보존은 [수집 지침](factor-collector-instructions.md), 판정은 [AEP 계약](02-authorized-evidence-panel-v1.md)을 따른다. 규칙 변경은 이 문서에 반영하고 이전 규칙은 Git 이력에서 확인한다.

## 1. 저장과 사용

- 작품별 파일 하나를 사용하며 배정받은 Work만 갱신한다. 파일 분리만으로 같은 Work의 동시 편집 충돌이 해결되지는 않으므로 중복 배정을 먼저 확인한다.
- 현재 canonical/candidate·registry·배정에서 Work와 대표 ISBN을 확인한다. 과거 후보 DB 경로나 리드의 서지 값을 현재 정체성의 근거로 사용하지 않는다.
- 기존 유효 raw·research·receipt를 먼저 재사용하고, 그 다음 이 리드의 URL을 확인한다. URL 확보나 `points` 작성만으로 실제 독해·수집 완료를 보고하지 않는다.
- 리드 JSON·수집 캐시·사용자 제공 원문은 Git에 포함하지 않는다. 사용한 자료와 의미 있는 변경은 [저장 계약](03-local-authoring-storage.md)에 따라 보존한다. `.workspace/user-sources/`는 보호 대상이며 임시 폴더라는 이유로 삭제하지 않는다.
- 새 freeze에 이 정식 리드 루트를 전달해도 현재 Work의 `<workId>.json`만 형식·Work를 검증해 결속한다. 다른 작품의 리드나 전체 폴더를 반복 복사하지 않는다. 별도 PDF·메모·raw는 [수집 지침](factor-collector-instructions.md)의 collector `start --input <정확한-파일>`로 Work collection에 명시적으로 결속한다. 이 파일 선택은 자료 채택·의미 판정 권한이 아니다.

## 2. 표준 JSON 스키마 및 작성 예시

다음은 형식 예시다. 꺾쇠 안의 문자열과 `example.org` URL은 설명용 자리표시자이며 실제 입력에서는 확인한 Work·판본·출처로 바꾼다. 실제 작품의 조사 결과나 유효 판정 입력이 아니다.

```json
{
  "workId": "<배정된 Work ID>",
  "title": "<확인한 일본어 작품명>",
  "creators": "<확인한 작가명>",
  "publisher": "<해당 판본의 출판사>",
  "isbn": "<현재 대표판의 13자리 ISBN>",
  "sources": [
    {
      "url": "https://example.org/publisher/edition",
      "kind": "official",
      "points": "<이 페이지에서 확인한 해당 판본·레이블·소개와 한계>"
    },
    {
      "url": "https://example.org/review/article",
      "kind": "review",
      "readingScope": "<본문에서 확인한 실제 권·회차 범위>",
      "points": "<해당 리뷰에서 확인한 구체적 관찰과 한계>"
    }
  ]
}
```

| 필드                             | 형식·의미                                                                                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `workId`                         | 배정된 정확한 Work ID 문자열. 제목 유사성만으로 다른 Work에 결속하지 않는다.                                                                           |
| `title`, `creators`, `publisher` | 확인한 작품명·작가·해당 판본 출판사 문자열. 미확인 값을 추정하지 않으며 기존 리드와 현재 서지가 다르면 확인할 gap으로 남긴다.                          |
| `isbn`                           | 현재 대표판의 13자리 ISBN 문자열. 중간 권·전자판·한정판이라는 이유로 1권 일반판으로 교체하지 않는다. 판본 정정은 원문 근거와 새 revision으로 처리한다. |
| `sources`                        | 출처 객체 배열. 배열 길이는 최소 조사량·완료·승격 기준이 아니다. 유효한 출처를 보존하되 개수를 늘리기 위한 탐색은 하지 않는다.                         |
| `sources[].url`                  | 실제 공개 출처 URL. 검색 결과 제목·사이트 홈만으로 해당 작품 본문이 존재한다고 간주하지 않는다.                                                        |
| `sources[].kind`                 | `official` 또는 `review`. 출처 역할의 리드 분류이며 safety/context/factor 채택은 별도 동결 판정에서 결정한다.                                          |
| `sources[].readingScope`         | 리뷰에서 확인한 실제 범위 문자열. 확인할 수 없으면 생략 또는 `null`. URL·상품 권수만으로 리뷰의 독서 범위를 추정하지 않는다.                           |
| `sources[].points`               | 해당 출처에서 확인한 관찰과 한계의 요약 문자열. 원문·수치 판정·SAFE 인증을 대신하지 않는다. 아직 읽지 않은 본문의 내용은 작성하지 않는다.              |

이 형식은 리드 전용이다. collector의 `research.jsonl`, `readAudit`, publisher receipt, frozen job을 대신하지 않으며 편의를 위해 새 권한 필드나 자동 PASS 값을 추가하지 않는다.

## 3. 자료 수집 및 채택 적격성 기준

### 공식 자료

- 해당 작품·판본의 출판사 상품 페이지, 공식 연재·레이블 페이지, 실제 서지를 확인할 수 있는 유통사 자료를 사용한다. 제목·작가·대표 ISBN·권수·판본을 정확히 대조한다.
- 안전 분류는 해당 작품에 결속된 출판사·레이블 근거의 **porn / non-porn**이다. 성인등급·폭력·성적 소재·표현 강도 자체는 제외나 추가 조사 사유가 아니다. 출판사 이름만으로 모든 작품을 일괄 SAFE 처리하지 않는다.
- 공식 시놉시스도 실제 내용을 지지하는 범위에서만 관찰로 사용한다. 서점의 사용자 리뷰는 공식 소개와 구분하며 공식 안전 분류로 전용하지 않는다.
- 출판사 소개를 취득하면 같은 수집분의 원문·receipt·서지 입력을 함께 보존한다. 실제 HTTP 응답·시각이 없는 발췌를 publisher receipt로 만들지 않는다.

### 리뷰·비평

- 독서미터·note·개인 블로그·웹진·커뮤니티·판매 사이트 사용자 리뷰 등에서 **동일 만화의 구체적 사건·관계·톤·구성 및 실제 읽은 범위**를 확인한다. 도메인이나 글 길이만으로 채택·배제하지 않는다.
- 장문 리뷰는 유용한 탐색 대상이지만 길이가 근거 품질을 보장하지 않는다. 단순 호불호·별점·짧은 잡담은 팩터 관찰을 대신하지 않는다. 한 페이지의 상품 판본과 개별 리뷰의 범위는 따로 확인한다.
- 같은 소개를 복제한 페이지는 독립 관찰로 부풀리지 않는다. 작성자·날짜·반대 근거·접근 한계를 실제 출처별로 남긴다. 작성자가 미확인이면 research에서 `author=""`, `authorRole="unknown"`을 유지한다.
- 1~3권·전권 독해·직접 패널·리뷰 최소 개수를 일률적으로 요구하지 않는다. `whole_work`는 주장 범위이며 확보한 관찰의 실제 범위와 한계는 별도로 보존한다.
- 신규 Art 4축은 수집·판정 범위에서 제외한다. N/T 부족은 실제 추가 조사·출처 소진 기록을 [AEP 계약](02-authorized-evidence-panel-v1.md)에 결속하며 리드 목록만으로 소진을 추정하지 않는다.

### 선정·추천 문맥과 부적격 자료

- registry `supportEvidenceUrls`의 **정확한 URL**에서 해당 작품의 선정·추천 사실을 확인하고 동일 Work의 research/evidence ID에 연결한다. 임의의 비슷한 URL로 대체하지 않는다.
- 선정 목록·순위·별점은 선정 문맥을 입증할 수 있지만 그 자체로 서사·톤·테마의 근거가 되지는 않는다. 순위 형식의 글에도 구체적 작품 비평이 있으면 그 구간을 구분해 사용한다.
- 영화·애니 등 다른 매체, 작품 식별이 안 되는 발췌, 미독해 뷰어 셸, 원문 없는 요약·스포일러 이미지, 커뮤니티의 자의적 안전성 평가는 필요한 만화 관찰이나 공식 안전 분류를 대신하지 못한다.
- 접근 실패·로그인·유료·종료 자료는 한계를 보존하고 다른 공개 자료를 찾는다. 인증·차단 우회는 하지 않는다. 탐색 실패를 작품의 불호나 0점으로 바꾸지 않는다.

## 4. 조사 종료와 인계

구체적 gap이 해결되거나 새 정보가 더 나오지 않고 접근 가능한 관련 경로가 소진되면 종료한다. 출처 수를 채우거나 이미 충분한 리뷰보다 더 좋은 리뷰를 찾으려고 연장하지 않는다. 자료 부족은 부족한 사실·조사 시도·재개 조건으로, 시간·쿼터·사용자 중단은 실제 중단 사유로 구분한다.

수집 완료는 실제 원문·관찰·receipt와 저장 결과로 보고한다. 원문 저장·배치 단계 전환·판정·발행은 각각 [수집 지침](factor-collector-instructions.md), [배치 계약](01c-catalog-batch-promotion-plan.md), [저장 계약](03-local-authoring-storage.md)을 따른다.
