## 1. 목표

사용자가 **핵심 취향과 근거 확인 → 추천 반영 설정 변경 → 아래 미리보기에서 선두 추천의 변화 확인**을 자연스럽게 이어가게 한다. 추천 엔진·분석값·영속성은 그대로 두고, 미리보기의 정확성·모바일 밀도·도구 영역 위계·선반 발견성을 개선한다.

## 2. 유지할 제품 계약

- 추천과 분석은 기존 deterministic engine을 사용한다. runtime LLM, 새 추천 산식, 서버 API, DB/schema, 의존성을 추가하지 않는다.
- 상위 3은 축·테마·장르 전체에서, 레이더는 확인된 대표 축 최대 7개에서 선택한다. 두 집합을 억지로 일치시키지 않는다.
- 팩터 사전의 일본어 레이블과 기존 정성 강도를 사용한다. 숫자 원값을 노출하거나 같은 강도 레이블을 인위적으로 다르게 만들지 않는다.
- FactorBar는 읽기 전용 분석이다. 장르에는 보정이 없고, 나머지 네 범주의 모든 5단 선택을 유지한다. 테마 22항목을 일부만 남기지 않는다.
- 범주는 처음에 모두 접고 하나만 연다. `group` URL, 즉시 저장, 구체적인 저장 스낵바, 실패 복구, reveal 1회·reduced motion을 유지한다.
- 실제 표지·캐시·원본 비율·기존 상세 링크를 재사용한다. 분석 근거와 최근 기록의 역할을 유지한다.
- 모든 제품 문자열은 `src/lib/strings.ts`, 크기·간격은 기존 semantic token을 사용한다.

## 3. 1차 — 추천 미리보기의 정확성과 중복 제거

### 비교 의미

현재 구현은 같은 최신 Catalog·기록·추천 정책에 대해 **이 페이지에서 처음 읽은 보정 설정**과 **현재 보정 설정**을 적용하고 각각 선두 최대 4개 ID와 순서를 비교한다. 방문 당시의 작품 목록을 고정하는 기능이 아니다. 새로고침하면 현재 저장된 보정이 새 기준이 된다. `調整前`만 쓰면 직전 조작 이전으로 오해할 수 있으므로 방문 기준을 남긴다.

| 용도           | 제안 문구                                                                                     |
| -------------- | --------------------------------------------------------------------------------------------- |
| 제목           | `おすすめへの反映を比較`                                                                      |
| 기준 열        | `開いたときの反映設定で`                                                                      |
| 현재 열        | `現在の反映設定で`                                                                            |
| 설명           | `今の記録とおすすめ方針に、それぞれの反映設定を適用した結果です。先頭の最大4作品を比べます。` |
| 동일           | `先頭の最大4作品に変化はありません。`                                                         |
| 변경           | `先頭の最大4作品の顔ぶれや並びが変わりました。`                                               |
| 작품 정보 누락 | `この作品の情報を表示できません。`                                                            |

`最大4作品`이므로 결과가 1–3개여도 맞는다. 실제 개수별 문구 함수를 추가하지 않는다. 추천 화면은 기존 Top 10이며 미리보기는 같은 엔진 순서의 선두 최대 4개다. 5위 이하 불변을 주장하지 않는다. 워크스페이스 기존 설명 끝에 `結果は下の比較で確認できます。`를 넣어 결과 위치를 알린다.

### 표시 상태

| 실제 결과               | 표시                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------ |
| 동일하고 1개 이상       | 현재 추천 한 줄 + 변화 없음 상태. 이전 목록을 중복 렌더하지 않는다.                  |
| 작품 또는 순서가 변경됨 | 조정 전/현재 두 목록과 변화 상태를 바로 보여 준다. 추가 펼치기 버튼을 만들지 않는다. |
| 양쪽 모두 0개           | 기존 추천 없음 안내 한 번. 빈 두 목록과 변화 없음 문구를 만들지 않는다.              |
| 한쪽만 0개              | 전후 비교를 유지하고 빈 쪽은 추천 없음으로 표현한다.                                 |
| 계산 불가               | 기존 이용 불가 안내를 유지한다. 변화 없음으로 대체하지 않는다.                       |

내부 비교 키는 work ID를 유지한다. 화면의 `work ID` 설명, `sr-only` ID, 누락 작품의 raw ID 출력만 제거한다. 정상 작품 링크 이름은 제목이다. 누락 작품은 링크 없는 안내로 해당 자리를 유지하며 비교 배열에서 조용히 삭제하지 않는다. 별도 placeholder 컴포넌트·가상 표지는 만들지 않는다.

현재 목록은 같은 컴포넌트 위치와 작품 key를 유지하고 기준 목록만 조건부 표시한다. 기존 `unchanged` 계산과 `WorkPreviewList`를 재사용한다. 상태 문장만 기존 `aria-live`에 두고 전체 표지 목록을 live 영역에 넣지 않는다. 정상 보정 조작 중 라디오 focus·스크롤을 강제로 이동하거나 빈 두 줄 높이를 예약하지 않는다. 실제 focus된 링크가 제거되는 흐름이 확인될 때만 가까운 의미 있는 위치로 복구한다. 선제적인 focus 관리 계층은 만들지 않는다.

**수용 기준:** 위 5개 상태와 작품 누락이 구분된다. 동일 결과가 중복되지 않는다. 새로고침 후 기준 재설정, 저장 실패 시 선택·미리보기 rollback, 기록/정책 변경 시 두 설정의 재계산 의미를 유지한다. FactorBar는 변하지 않는다. 미리보기 선두 최대 4개와 추천 화면 Top 10의 공통 순서가 같은 입력에서 일치한다. 비교 범위를 넘는 주장과 사용자에게 노출되는 ID가 없다.

**1차 구현 확인:** 별도 개발 origin의 실제 보정 UI에서 동일 목록 하나→학원 제외 저장→변경 목록 둘→추천 Top 10 선두 일치→재진입 후 제외 유지·새 기준을 확인했다. 학원 막대의 `aria-valuenow`는 변경 전후 `1.379310344828`로 같았다. 빈/계산 불가/누락 분기는 기존 테스트 파일에 보완했으나 사용자 지시에 따라 실행하지 않았다. 저장 실패는 이번 흐름에서 실행하지 않았다.

## 4. 2차 — 모바일 상위 요약과 레이더

- 상위 취향은 기존 순위 1열 목록을 유지한다. 각 행의 첫 줄은 순위·이름·16px 강도, 다음 줄은 근거 제목으로 구성한다. 이름은 최대 2줄, 강도는 nowrap, 근거는 1–2줄이다. 한 줄짜리 근거에도 강제로 두 줄 높이를 예약하는 부분과 불필요한 행 간격을 줄인다.
- desktop `>=768`의 3열·28px 강도 계약은 유지한다. 실제 768px에서 기존 헤더 2열 때문에 강도 문구가 겹쳤으므로 **요약/레이더의 2열 시작만 1024px로 이동**했다. 상위 취향 카드의 3열 시작은 768px 그대로다. 큰 화면은 요약에 1.1fr·레이더에 0.9fr를 배정하고 레이더 최대폭은 기존 Taste 토큰의 절반(480px)이다. §4 반응형 계약에도 반영했다.
- 기존 레이더 제목을 `代表的な軸の傾向`처럼 명확히 한다. 새 설명 문단으로 모바일 높이를 늘리지 않는다. 동일 값을 가진 접근 가능한 목록과 장식 SVG의 역할을 유지한다.
- 먼저 상위 요약에서 높이를 줄인다. 레이더 라벨을 줄이거나 잘라서 한 화면에 맞추지 않는다. 실제 사전의 긴 라벨이 경계를 벗어나면 기존 SVG의 줄바꿈·anchor·여백을 같은 컴포넌트에서 수정한다.
- 일반 진입의 대표 390×844 화면에서는 레이더 전체를 탭 위에서 읽을 수 있는 첫 화면 배치를 목표로 하되 **첫 화면 완전 수납은 합격 조건이 아니다**. 실제 탭 상단을 기준으로 확인한다. 320px·200% 확대·긴 콘텐츠·safe area에서도 스크롤하면 모든 라벨과 조작에 접근할 수 있어야 한다. 특정 프로필에 맞춰 높이나 축을 고정하지 않는다. 잘림 재현 없이 viewBox·반지름·글자 크기를 변경하지 않는다.
- 공통 앱 셸이 이미 확보한 하단 64px 여백을 재사용한다. Taste 본문에 같은 여백을 추가하지 않는다.

**수용 기준:** 현재 프로필과 긴 사전 레이블에서 좌우 텍스트 잘림이 없다. 차트가 작아져 이름을 읽기 어려워지지 않는다. 근거 제목·상위 순위·정성 강도·7축 데이터가 보존된다. 마지막 라디오와 마지막 기록은 스크롤과 키보드로 접근 가능하다.

## 5. 3차 — 조정 영역의 폭과 제목 위계

- `/taste` 전체를 기존 `--layout-width-taste`(최대 960px)에 맞춘다. loading/일반 화면 모두 같은 바깥 폭을 사용하고 DNA·근거 선반·조정·미리보기·최근 기록의 기준선을 통일한다. 상단 1200px/하단 960px 이중 폭을 제안했던 초안은 철회한다. `04` §2.4의 Taste 960px와 `03` §4 범주 row 상한을 따르며, 기존 1200px 구현 때문에 계약에 예외를 추가하지 않는다. 새 width token이나 wrapper 컴포넌트는 필요 없다.
- `最近の記録` 제목에 미리보기와 같은 `--text-subheading-size`를 명시한다. desktop 20px/mobile 16px이며 조정 workspace 제목보다 작다.
- 조정 제목과 설명은 자연스럽게 줄바꿈되게 한다. 두 열 설명, 분석 막대와 라디오, sticky heading의 기존 의미를 유지한다.
- 장르 요약은 `分析のみ（10項目）`로 항목 수와 분석 전용 의미를 함께 알린다. 장르 열기 버튼은 `内訳を見る`, 접근 가능한 이름도 범주를 포함한 분석 내역 의미로 제안한다. 다른 범주의 `詳細設定`과 기존 닫기 표현은 유지한다. 장르 버튼 예외는 구현 시 §4 표시 계약과 함께 반영한다. 같은 의미의 추가 설명 문단은 만들지 않는다.
- 확신도는 기존 정성 상태를 유지한다. 큰 배지·새 점수·새 강조색은 추가하지 않는다.

**수용 기준:** 전체 shell과 조정 행이 960px 상한을 지킨다. 섹션 기준선이 같고 최근 기록 제목이 미리보기보다 크지 않다. 768px에서 분석/반영 열·5단 조작·focus 링이 잘리지 않는다. 장르는 10개 막대·라디오 0개를 유지하며 설정 가능성을 암시하지 않는다.

## 6. 4차 — 모바일 근거 선반의 다음 작품 힌트

- 기존 `MediaShelf`와 네이티브 가로 스크롤을 사용한다. Taste 카드 폭만 조정해 390px에서 두 작품 뒤에 세 번째 표지 일부가 보이게 한다. 기존 간격 토큰 기준 약 24px 이상의 힌트를 목표로 하되 제목·근거 레이블 가독성을 우선한다.
- 320px에는 두 장을 강제하지 않는다. 한 장과 다음 장 일부를 보여 주는 배치를 허용해 읽을 공간을 확보한다. 큰 desktop에서는 960px shell 안의 5작품 한 줄을 유지한다. 실제 track의 안쪽 패딩과 간격을 포함해 폭을 정하며, 바깥 패딩만 뺀 추정치로 CSS 값을 고정하지 않는다.
- 숨긴 화살표를 억지로 축소하거나 새 페이지 표시·carousel dependency·복제 트랙을 추가하지 않는다. 가로 스크롤과 기존 키보드 이동으로 마지막 작품에 접근할 수 있어야 한다.

**수용 기준:** 넘치는 선반의 첫 위치에서 다음 카드 일부가 보이고, 5번째 작품까지 접근된다. 실제 표지 원본 비율·제목 2줄·근거 레이블·상세 링크·focus 링이 유지된다. 다른 페이지 선반의 폭과 동작은 바뀌지 않는다.

## 접근성 검토에서 추가된 확인 사항

`FactorPanels`의 key가 `group`에 따라 바뀌어 disclosure를 포함한 하위 트리가 다시 마운트됐고, 실제 Enter 열기에서 포커스가 BODY로 사라졌다. key를 제거하고 route 사용 시 URL의 group을 직접 사용하도록 수정했다. 독립 컴포넌트의 로컬 열기 상태는 유지한다. 수정 뒤 열기/닫기와 브라우저 뒤로/앞으로에서 같은 버튼 포커스와 한 범주 상태를 확인했다.

가로 스크롤 보정 그룹의 `p-0`이 2px outline + 2px offset을 잘랐으므로 Taste 그룹에 기존 `--space-1`(4px)을 적용했다. **추가로 재현된 공통 원인:** 1px 숨김 radio에 대한 네이티브 포커스 스크롤이 표시 레이블 전체를 드러내지 않아 320px에서 선택된 「除外」가 화면 밖에 남았다. 공통 ChoiceChip의 radio/checkbox 모두 표시 label을 `nearest`로 스크롤하고 4px outline 여백을 포함하도록 수정했다. 이는 처음 계획한 공통 컴포넌트 무변경에서 확장된 최소 근본 수정이다. Taste 저장 알림이 현재 포커스와 실제로 겹칠 때만 해당 항목을 스크롤하며 포커스를 바꾸지 않는다. BODY 또는 다른 페이지 포커스에는 적용하지 않는다. 근거 선반의 끝 focus ring도 Taste track의 4px 여백으로 보존한다.

320px에서 기존 `html min-width:320px`와 stable scrollbar gutter가 합쳐져 문서 가로 넘침이 생겼다. 불필요한 최소폭 한 줄만 제거하고 사용자가 요청한 stable gutter는 유지했다. 수정 후 320px viewport의 문서 client/scroll width는 모두 305px였다. 물리 터치·실제 스크린리더·비영 safe-area는 미확인이다.

## 8. 구현 시 검증과 종료 조건

1. 기존 일반 `/taste` 진입에서 상위 취향→레이더→근거 선반→장르/보정 상세→미리보기→최근 기록을 확인한다. 390×844, 320px, 768px 경계, 기존 1641×1149와 200% 확대를 사용한다.
2. 사용자 프로필을 직접 덮어쓰지 않고 별도 개발 origin의 기존 온보딩/Import/설정 UI로 필요한 상태를 만든다. 직접 DB 주입·테스트 전용 제품 경로는 만들지 않는다.
3. 같은 결과/달라지는 결과, 새로고침·범주 URL 왕복 후 저장값, FactorBar 불변, 미리보기 선두 최대 4개와 추천 화면 Top 10의 공통 순서를 확인한다. 저장 실패를 실행한 경우 선택·미리보기 rollback과 focus를 확인한다. 양쪽 0개·한쪽 0개·계산 불가·누락 작품은 따로 구분한다. 자연스럽게 도달할 수 없는 오류 조건은 기존 경계 테스트로만 보완하고 실제 제품 흐름 PASS로 쓰지 않는다. 새 fixture·harness·제품 API를 만들지 않는다.
4. 현행 §4 수용 기준 15개 원문을 구현 검증 기록에 그대로 두고 이번 범위의 확인/미확인/비해당을 항목별로 남긴다. reveal·normal 코칭·저장 실패·reduced motion은 실행한 경우만 PASS로 기록한다.
5. 사용자 지시대로 현재 자동 테스트 명령·typecheck·build는 실행하지 않는다. 테스트 파일의 보완 계획이 실행 증거를 의미하지 않는다. 향후 푸시에는 당시 유효한 지시와 저장소 필수 검사를 적용한다.
6. 같은 화면 크기·프로필·상태의 전후 캡처를 비교한다. disclosure와 열린 테마 첫·마지막 라디오, 가로 스크롤된 `除外`, 선반 마지막 작품, 미리보기의 focus를 별도로 확인한다. 캡처는 가림·문구·배치의 근거이며 영속성·낭독 증거가 아니다. 요청 결과와 관련 필수 검증을 충족하면 종료한다.

## 9. 외부 검토 완료

사용자가 지정한 Cursor CLI `cursor-grok-4.6-xhigh`와 agy CLI `gemini-3.8-flash-high`/effort high에서 각각 **세 개의 별도 shell·새 세션을 병렬 실행**했다. 여섯 세션 모두 UI/UX 디자이너 역할을 받았고, 완료된 결과를 회수했다.

- 역할 1: 모바일 레이아웃·시각 위계·근거 선반.
- 역할 2: 추천 조정 UX·미리보기 의미·일본어 카피·상태 전이.
- 역할 3: 접근성·기존 계약·최소 변경 범위·검증 계획.

양쪽에 동일한 압축하지 않은 초안·소스·계약·캡처와 46개 파일 ledger/root identity를 제공했다. 여섯 초안 판정은 모두 REVISE였다. 이 문서는 그 의견을 소스·상위 계약·기존 관찰에 대조해 종합한 수정안이며, 외부 모델이 수정안까지 재검토했다고 주장하지 않는다. 채택·기각 근거와 실행 신원·재시도·검토 한계는 [검토 종합](taste-plan-review-20260912.md)에 남겼다.
