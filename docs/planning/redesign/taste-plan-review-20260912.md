# Taste 개선 계획 — 외부 검토 종합

**결론:** Cursor Grok 4.6 xhigh 3명과 Antigravity Gemini 3.8 Flash high 3명의 독립 UI/UX 리뷰를 회수했다. 여섯 초안 판정은 모두 **REVISE**였다. 소스·현행 계약·앞선 실제 화면 조사에 대조해 [개선 계획](taste-improvement-plan.md)을 수정했다. 수정안은 조정자의 종합이며 외부 모델의 재승인이나 구현 완료를 뜻하지 않는다.

이번 변경은 계획·종합 문서 두 개다. Taste 제품 코드·규범 사양·사용자 데이터는 변경하지 않았고 테스트·typecheck·build·새 브라우저 검증은 실행하지 않았다.

## 최종 계획

| 순서 | 변경 | 사용자에게 생기는 차이 |
| --- | --- | --- |
| 1 | 미리보기의 선두 최대 4개 범위·방문 기준 명시, 동일 결과는 한 목록, 빈/불가/누락 구분 | 무엇을 비교했고 실제로 무엇이 달라졌는지 이해한다. |
| 2 | 모바일 상위 취향의 빈 예약 높이 제거, 레이더 제목 정리, 라벨 보존 | 핵심 취향과 근거를 더 짧게 읽되 스크롤로 모든 정보를 확인한다. |
| 3 | 페이지 전체 최대 960px, 최근 기록 제목 20/16px, 장르의 분석 전용 버튼·요약 | 섹션 기준선과 정보 위계가 일치하고 장르를 설정할 수 있다고 오해하지 않는다. |
| 4 | Taste 근거 선반에 다음 표지 힌트, 좁은 화면의 제목·근거 가독성 보존 | 가로로 더 볼 작품이 있다는 점을 발견하고 마지막 작품까지 이동한다. |

테마 22개, 5단 보정, 장르 비보정, 읽기 전용 FactorBar, 즉시 저장, `group` URL, 결정론적 엔진, 실제 표지는 유지한다. 추가 접기·옛 mode 토글·새 carousel·runtime LLM은 넣지 않는다.

G1/G2/G3은 Grok의 역할 1/2/3, M1/M2/M3은 Gemini의 같은 역할이다. 발견 심각도는 모델의 자기 확신 수치가 아니라 실제 근거에 맞췄다.

### 입력 격리의 한계

G3는 CLI에 설치된 전역 `accessibility-simplicity-guard/SKILL.md`도 한 번 읽었다. 검토 디렉터리 안만 보라는 요청의 범위를 벗어난 추가 지침 참조다. 다른 리뷰나 사용자 데이터 열람은 도구 기록에 없지만, G3의 입력 전체가 46개 payload만으로 제한됐다고 주장할 수는 없다. 해당 리뷰의 유효 지적은 조정자가 저장소 근거로 다시 대조했으며, 여섯 결과의 일치 자체를 독립 검증이나 승인으로 쓰지 않았다.

### Gemini 재시도와 정리

첫 비대화형 시도는 파일 읽기 승인을 받을 수 없어 응답이 비어 있었다. exit 0이어도 리뷰 성공으로 세지 않았다. TTY 세 개에서 검토 폴더를 신뢰하고 파일 읽기를 진행했으나 요청이 파일마다 반복됐다. 공식 [Antigravity CLI 권한 문서](https://antigravity.google/docs/cli/permissions/)의 경로 한정 `read_file` 규칙을 사용해 frozen evidence 디렉터리만 임시 허용한 새 세션으로 실행했다. M2는 해시 조회 shell 명령의 승인이 없어 중단되어, shell 없이 읽기 도구만 쓰도록 새 세션으로 다시 실행했다. 공통 evidence와 역할은 같으며 추가 실행 제약은 원문 프롬프트에 보존했다.

완료된 여섯 세션의 도구 기록은 파일 읽기·검색뿐이다. 제품 코드 수정·테스트·사용자 브라우저 접근은 없었다. 임시 읽기 규칙과 이번에 추가한 검토 폴더 trust 항목·설정 백업을 제거하고 readback으로 확인했다. 사용자 요청에 따라 완료된 리뷰 쉘을 정리했으며, 재시도를 포함한 기록된 13개 shell PID와 자식 프로세스의 잔존 수는 0이었다.
