# Library 관리 흐름 개선안

상태: **사용자 승인 후 로컬 구현 반영**. 2026-09-11 리뷰의 수정 사항과 후속 페이지네이션·하단 배너 전체 폭 요청까지 반영했다. 현행 계약은 `03-ux-screen-contracts.md` §7과 `08` URL 표이며, 항목별 실제 확인과 남은 한계는 루트 `design-qa.md`에 기록한다. 커밋·푸시·배포는 이번 요청 범위가 아니다.

## 1. 목표와 판단 근거

주요 작업을 **내 책 찾기 → 한 권의 상태 확인 → 기록 수정**으로 잡는다. 기본 화면은 하나의 컬렉션이며, 작품은 현재 결과에 한 번만 표시한다.

검토 기준 HEAD는 `9943442`다. 직접 검증한 브라우저에는 17작품(읽고 싶음 2, 읽음 15)이 있었고, 사용자가 제공한 외부 리뷰에는 10작품이 모두 읽음 상태였다. 기록 수와 화면 폭이 달라 수치끼리 비교하지 않는다. 모바일 탭 겹침, 검색 0건 안내, 동일 작품 중복, 보기 전환의 일부 적용은 두 리뷰에서 일치한다.

| 구분        | 계획에 반영하는 근거                                                                                                                                                              |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 직접 재현   | 390px에서 검색창 위치를 클릭하면 하차 탭이 선택됨. 검색 0건 안내 누락/오안내. 한 검색 결과가 최근·상태 영역에 중복. 리스트에도 recent 캐러셀이 유지됨. 추가 검색 결과의 표지 누락 |
| 소스로 확인 | 변경 여부와 무관하게 저장 버튼 활성화. 진행 권/화 입력 상시 노출. 카드의 400px 표지와 편집창의 기본 200px 요청이 다름                                                             |
| 추가 확인   | 편집창을 여는 순간 표지가 비는 시간과 조건. 하단 내비게이션이 마지막 카드나 포커스된 조작을 스크롤해도 가리는지. 실제 모바일 키보드와 200% 확대                                   |

하단 바가 스크롤 중인 콘텐츠 일부를 가리는 사진만으로 여백 결함을 확정하지 않는다. `tabpanel`의 `tabIndex=0`도 그 자체로 오류가 아니므로 실제 키보드 흐름을 확인한 뒤 결정한다.

## 2. 승인된 기본 화면

위에서 아래로 다음 순서를 사용한다.

1. **간결한 제목과 `作品を追加`**: 현재 타이포·색상 토큰과 기본 CTA를 사용한다. 큰 상태 매트릭스와 중복되는 페이지 설명은 제거한다.
2. **내 기록 검색**: `ライブラリ内の作品・作者を検索`로 검색 범위를 명시한다.
3. **상태 탭**: `すべて` + 기존 상태 5종을 유지하고 모든 화면 크기에서 등록 건수를 붙인다.
4. **즐겨찾기 조건·정렬·보기·표시 건수**: `お気に入りのみ`는 탭 줄 밖의 별도 조건 버튼이다. mobile에서는 조건·정렬 다음에 표시 건수·보기를 배치한다.
5. **하나의 작품 목록과 페이지네이션**: 전체·상태 선택·검색·즐겨찾기에 같은 필터·정렬 결과를 사용하고 페이지당 최대 24개를 표시한다.
6. **조용한 데이터 안내**: 기본 목록 하단에서 기존 설정 링크를 유지한다. 후속 사용자 요청에 따라 desktop/mobile 모두 본문 전체 폭이다. 검색 중이거나 필터 결과가 0건이면 배너를 표시하지 않는다.

### 컬렉션과 중복 제거

- 전체 보기에서 최근·상태별·favorite 캐러셀을 별도로 렌더하지 않는다. 상태가 섞여 있어도 같은 원칙을 적용한다.
- 중복 제거는 동일 기록의 반복 렌더에 적용한다. Catalog/external 기록의 identity와 union 규칙은 유지한다.
- 최근 업데이트는 기존 `最近更新` 정렬이 담당한다. 읽은 작품만 있을 때 선반을 숨기는 예외 규칙을 추가하지 않는다.
- 즐겨찾기 탐색 능력은 `お気に入りのみ`로 유지한다. 현재 `reaction === "favorite"` 조건을 재사용하며, 새로운 읽음 상태로 취급하지 않는다.
- `그리드`는 세로로 이어지는 실제 CSS grid다. 모바일 390px에서 두 열을 기본으로 하고 가로 스와이프를 요구하지 않는다.
- `리스트`는 같은 작품·같은 순서를 조밀한 행으로 표현한다. 보기 전환으로 항목이나 정렬이 달라지지 않는다.

### 건수와 URL

- 탭의 건수는 검색어와 무관한 **등록 기록 수**로 유지한다. 목록 위에는 `1作品を表示`처럼 짧은 표시 수만 쓴다. 여러 페이지면 `1–24 / 200作品`으로 범위와 전체 결과 수를 표시한다.
- 기존 `state`, `q`, `sort`, `view`의 의미와 URL 복원·뒤로/앞으로 동작을 유지한다.
- 즐겨찾기 필터를 유지하기 위한 최소 확장으로 선택 시에만 `favorite=1`을 사용한다. 기존 URL의 결과는 바뀌지 않으며 잘못된 값은 기본 상태로 정규화한다.
- `favorite`는 화면 표시 조건이다. Dexie 기록 스키마나 추천 입력을 바꾸지 않는다.
- 전체 기록을 검색·필터·정렬한 뒤 24개씩 나눈다. 2페이지부터 `page`를 URL에 저장하며 q/state/favorite/sort 변경은 1페이지로 초기화하고 view 변경은 유지한다. 범위 초과는 마지막 페이지로 replace 정규화한다. 기존 Button·NativeSelect의 이전/페이지 선택/다음으로 이동하고 결과 목록에 포커스를 옮긴다.
- 표지 resolver 대상은 현재 페이지와 열린 편집/추가 검색 결과다. visibility demand·cache·ISBN 중복 제거와 기존 4개 동시 처리 상한을 재사용한다. 개발 환경의 1초 요청 간격은 기존 동작이며 모든 환경의 제공자 rate limit을 보장한다는 의미가 아니다. 페이지가 바뀌면 이전 generation의 대기 작업은 중단하고 이미 시작한 요청은 완료한다.

## 3. 검색과 빈 상태

| 상태                              | 안내와 다음 행동                                                                        |
| --------------------------------- | --------------------------------------------------------------------------------------- |
| 등록 기록 자체가 0                | 기존 승인된 empty image-half와 `作品を追加` 유지                                        |
| 검색어 없이 선택 상태만 0         | 해당 상태의 기록이 없다고 안내. `すべての作品を見る`로 기존 기록을 찾을 수 있게 함      |
| 검색어가 있고 결과가 0            | 검색어를 포함한 `「…」に一致する作品は見つかりませんでした。` 표시. `検索をクリア` 제공 |
| 검색어 + 상태/즐겨찾기 조건으로 0 | 검색 0건 안내와 함께 적용 조건 표시. 조건이 있을 때만 `絞り込みを解除` 제공             |
| 검색 결과 존재                    | 한 목록과 실제 결과 수 표시. 최근/favorite 복제 영역 없음                               |

`検索をクリア`는 `q`만 지운다. `絞り込みを解除`는 상태·즐겨찾기 조건만 해제하고 검색어는 유지한다. 두 동작 모두 정렬과 보기 선택은 유지한다. 검색 결과 수 변경은 `aria-live="polite"`로 알린다.

## 4. 관리 카드와 편집

### 카드·리스트

- 기존 `LibraryStateCard`, `LibraryListCard`, `RowMedia`, 디자인 시스템 wrapper를 정리해 재사용한다. 표시 데이터와 편집 진입 경로를 공유한다.
- 기본 정보 순서는 **표지 → 제목 → 상태·감상 → 기록된 진행 정보**로 통일한다. 없는 감상이나 진행을 빈 수치로 만들지 않는다. 읽는 중 progress bar는 저장된 volume과 확인된 총 권수가 있을 때만 표시한다.
- 전체 보기에서는 상태를 보여주고, 단일 상태 필터에서는 모든 카드에 같은 상태 배지를 반복하지 않는다. `カタログ外`·catalog-missing 구분은 항상 유지한다.
- 업데이트 날짜는 편집 시트의 보조 정보로 옮긴다. `updatedAt`을 읽은 날짜나 독서 활동 이력으로 바꾸어 표현하지 않는다.
- 카드 전체는 기존처럼 기록 편집 버튼이다. 작은 `記録を編集` 표시로 동작을 눈에 보이게 하고 hover에만 의존하지 않는다. 내부에 버튼을 중첩하지 않는다.
- 리스트는 표지를 줄이고 제목·상태·감상·진행을 옆으로 배치한다. 긴 제목과 모바일에서는 줄바꿈하며 높이는 내용에 맞춘다. 44px 조작 영역을 유지한다.

### 편집 시트

- Catalog/external 상세 링크, 상태 5종, 감상, 이유와 기존 저장 경로를 유지한다.
- 초기 포커스는 제목(`tabIndex=-1`)에 두고 Tab으로 필드에 진입한다. 닫기·Escape·포커스 트랩·원래 카드 복귀를 보존하고 상태 변경으로 카드가 현재 필터에서 사라지면 활성 탭으로 돌아간다.
- 실제 변경이 없거나 수정값이 원래 값으로 돌아오면 `変更を保存`을 비활성화한다. 무변경 저장으로 `updatedAt`만 갱신하지 않는다.
- 진행 입력은 `進み具合（任意）`로 명시한다. 읽는 중이거나 이미 진행 기록이 있으면 펼치고, 나머지는 기본 접힘으로 둔다. 접었다는 이유로 기존 값을 지우지 않는다.
- 표지는 여는 카드의 실제 `currentSrc`와 요청 크기를 편집창에 그대로 전달한다. 이미 200px fallback이 로드된 카드도 같은 URL을 사용한다. 원본 비율과 공유 CoverImage의 실패 경로는 유지한다.
- 저장 성공 안내는 기존 쓰기·readback 결과에 근거한다. 실패 시 수정값과 재시도 가능 상태를 보존한다.

## 5. 작품 추가와 보조 안내

- 페이지 검색은 내 기록 필터, 추가 시트 검색은 Catalog/외부 작품 추가임을 문구로 구분한다. 추가 입력은 `追加する作品名・作者名`을 사용한다.
- 추가 시트의 초기 포커스는 검색창에 둔다. 모바일에서는 실제 키보드가 검색 결과와 닫기를 가리지 않는지 확인한다.
- 로컬 검색 결과에도 기존 표지 resolver/cache 경로를 연결한다. 이미 등록된 작품뿐 아니라 검색 결과 work ID도 해결할 수 있게 하고, 화면에 보이는 결과의 표지만 요청한다.
- 이미 추가한 작품의 상태 보호, 외부 검색 실패 안내, Catalog ISBN 대조와 external identity 처리는 기존 경로를 유지한다.
- **Library 추가 시트의 판매순 배너는 유지한다.** 기존 승인 철회가 필요한 제거 결정만 사용자에게 별도로 물었으며 추가 답변은 없었다. 기존 `03` §5 범위와 추천 페이지의 배너·동작을 유지한다.
- 데이터 안내의 기존 이미지와 `/settings?section=data` 링크는 유지하되 검색 0건의 다음 행동으로 노출하지 않는다. Import/Export UI를 이 페이지에 복제하지 않는다.

## 6. 계약 변경과 구현 순서

큰 상태 매트릭스와 반복 Shelf를 요구하던 화면 계약을 승인된 관리 흐름으로 갱신했다. 이전 테스트가 recent/favorite 중복 카드를 기대한다는 이유로 그 구조를 남기지 않는다. 해당 검사는 단일 결과·정렬·페이지 경계 검사로 변경했고, 실행은 사용자 지시에 따라 푸시 전까지 보류한다.

- `docs/planning/03-ux-screen-contracts.md` §7: 정보 위계, 건수, 단일 목록, 빈 상태, 편집과 수용 기준.
- 같은 문서 §5 판매순 발견 배너: 기존 승인 범위 유지.
- `docs/planning/08-tanstack-start-migration.md` URL 표: 선택적인 `favorite=1`·`page` 추가.
- `docs/planning/redesign/screen-plans/06-library.md`: 선반 기반 구조를 컬렉션 기반 구조로 변경.
- 기존 `tests/unit/library/*`와 route-search 검사: 새 사용자 동작을 보호하도록 수정. 기존 record union·정렬·external 저장·이유 정규화 검사는 보존.

주 구현 파일은 `library-overview-header.tsx`, `library-view.tsx`, `library-media-cards.tsx`, `record-editor.tsx`, `modal-surface.tsx`, `work-search-sheet.tsx`다. 표지 연결은 `library-flow.tsx`와 기존 resolver를 사용한다. URL 확장은 `src/lib/route-search.ts`·`src/routes/library.tsx`와 Flow/View의 전달 경로에 함께 반영한다. 일본어 문구는 모두 `src/lib/strings.ts`에서 관리한다.

| 순서                   | 완결된 변경 범위                                                                                         | 종료 조건                                                                |
| ---------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 1. 조작 결함과 빈 상태 | 제목·추가 → 검색 → 탭 → 조건·정렬·보기 → 목록의 세로 순서, wrapping 탭 높이, 결과 0건 분기·해제 동작     | 390px 검색창을 눌러 실제 입력 가능. 0건 원인과 다음 행동이 명확함        |
| 2. 단일 컬렉션         | 화면 계약 갱신, 헤더 축소, 하나의 필터/정렬 결과, 실제 grid/list, 즐겨찾기 필터·URL, 반복 선반 제거      | 10작품이면 10개, 17작품이면 17개만 표시. 보기 전환 전후 ID와 순서가 같음 |
| 3. 기록 관리와 추가    | 카드 정보·편집 표시, 초기 포커스·무변경 저장·선택 진행 입력, 표지 전달, 추가 시트와 데이터 배너 우선순위 | 한 권 찾기→편집→결과 확인 흐름 완결. 이미 가진 기록과 표지 재사용        |
| 4. 최종 화면 검증      | 실제 브라우저 흐름과 영향받는 계약 확인                                                                  | 아래 수용 기준과 남은 한계를 항목별 기록                                 |

공유 `Tabs`·`CoverImage`는 변경하지 않고 Library 호출 설정과 기존 wrapper를 사용했다. 후속 사용자 요청으로 24개 단위 페이지네이션을 추가했다. 별도 가상화 라이브러리·서버 목록 API·새 검증 진입점은 필요하지 않다.

## 7. 수용 기준과 검증 경로

- [ ] 390×844, 1155×1149, 현재 데스크톱에서 탭·검색·정렬·보기 조작이 겹치지 않는다. 200% 확대와 긴 제목에서도 조작과 내용을 잃지 않는다.
- [ ] 검색창의 포인터 입력이 검색에 도달하며 탭 화살표 키·Tab·Escape·포커스 복귀가 동작한다.
- [ ] 마지막 카드와 포커스된 조작을 하단 내비게이션 위로 완전히 볼 수 있다. 가려짐이 재현될 때 필요한 clearance만 수정한다.
- [ ] 0개·1개·10개 모두 읽음·현재 17개 혼합 상태·200개를 점검하며, 각 작품은 필터 결과에 한 번만 나오고 한 페이지의 카드는 최대 24개다.
- [ ] 상태 5종, favorite 유무, Catalog/external/catalog-missing, 진행 기록 유무를 보존한다. 없는 통계나 프로필을 합성하지 않는다.
- [ ] 검색 성공·0건·상태+검색 0건·조건 해제에서 안내·표시 건수·등록 건수가 일관된다.
- [ ] grid/list 전환은 전체 결과를 바꾸고, ID·순서·검색·상태는 유지한다. 뒤로/앞으로·새로고침이 URL 조건을 복원한다.
- [ ] 변경 없는 저장은 실행되지 않는다. 값 수정→원복도 무변경으로 처리된다. 진행 입력을 접어도 기존 값은 보존된다.
- [ ] 실제 기록 편집의 저장 결과가 목록·건수·필터에 반영되고, 다시 열거나 새로고침하여 같은 기록을 읽는다. 실패 시 성공으로 안내하지 않는다.
- [ ] 추가 검색 결과와 편집 시트의 표지가 준비된 이미지와 같은 작품을 표시한다. 느린 로드·반복 열기·200px 폴백을 확인한다.
- [ ] 전체 빈 서재의 승인 이미지와 데이터 안내가 동시에 나오지 않는다. 검색 0건과 빈 상태 필터에서 데이터 배너가 주 행동을 대체하지 않는다.

주 검증은 실제 `/library` 진입과 UI 조작으로 한다. 현재 사용자 기록은 임의로 바꾸지 않고, 저장·다른 기록 규모가 필요한 검증은 별도 개발 브라우저에서 기존 제품의 추가/Import/편집 경로를 사용한다. 보조 테스트는 기존 파일에서 결함과 계약만 보호하며 새 E2E 시나리오나 검증 전용 진입점을 만들지 않는다. 기존 사용자 지시대로 필수 `typecheck`·`lint`·`test`는 푸시 직전에 실행한다. 이 계획 작성에서는 테스트나 데이터 변경을 실행하지 않았다.

구현의 실제 도달 경로·readback·각 수용 기준의 충족/미검증 구분은 루트 `design-qa.md`의 이번 변경 기록을 따른다. 계획에 적은 모든 검증 항목을 실행했다는 뜻은 아니다.
