# Taste 리뷰 재조사 — 2026-09-12

> 현재 제품을 조사한 의견이다. 구현 승인이나 새 화면 계약으로 사용하지 않는다. Taste 제품 코드는 변경하지 않았다.

리뷰의 미리보기·가로폭·제목 위계·근거 선반 지적에는 동의한다. 다만 모바일 하단을 영구적으로 읽거나 조작할 수 없다는 진단과 `padding-bottom`에 64px를 추가하자는 처방은 현재 화면에서 지지되지 않는다. 첫 화면에 레이더가 다 들어오지 않는 문제와 본문 끝에 접근할 수 없는 문제를 구분해야 한다.

## 조사 범위

- 대상: `http://localhost:3030/taste`, 일반 진입. 소스 기준 `a729d58`.
- 현재 저장된 Catalog 프로필, 확신도 `高い`, 보정 `すべて自動`을 사용했다. 상위 취향은 `迫力・スピード感`, `精神的な重さ`, `人物の変化・ドラマ`였다. 전달받은 리뷰의 작품·상위 취향과 다르므로 해당 리뷰의 왼쪽 라벨 잘림을 동일 프로필로 재현했다고 주장하지 않는다.
- 인앱 브라우저에서 1641×1149와 390×844를 설정해 실제 페이지를 열고, 스크롤·범주 열기/닫기·근거 선반 가로 스크롤을 수행했다. 사진 파일을 저장한 뒤 다시 열어 확인했다.
- 기록·보정값을 변경하지 않았다. 임시 화면 크기를 해제하고 감사 탭을 닫았다. 기존 Library 탭의 `?view=grid&state=planned` 상태를 보존했다.

## 추가로 확인한 중요한 문제

미리보기 함수는 추천 결과를 `slice(0, 4)`로 제한한 뒤 ID를 비교한다. 그런데 상태 문구는 `おすすめ順に変化はありません。`이다. 따라서 5위 이하만 바뀌었을 때도 전체 순서에 변화가 없는 것처럼 말할 수 있다. 이 조건은 소스에서 확인한 범위 문제이며, 실제 보정값을 바꿔 재현하지는 않았다.

현재 4작품 미리보기를 유지한다면 `表示中の4作品の並びは変わっていません。`처럼 범위를 명시하는 것이 가장 작은 수정이다. 전체 추천이 불변이라고 말하려면 실제 전체 비교 근거가 있어야 한다. 관련 구현은 `taste-flow.tsx`의 `recommendationPreviewWorkIds`와 `taste-insights.tsx`의 `RecommendationDiffPreview`, 문구는 `strings.ts`다.

## 권장 순서

1. 미리보기의 구현 용어·비교 범위 문구를 고치고, 변화 없을 때 중복 표지를 접는다.
2. 모바일 상위 요약과 레이더의 세로 구성을 줄인다. 해당 프로필에서 좌우 잘림이 재현되면 라벨 위치·차트 내부 여백도 함께 고친다. 공통 하단 여백은 중복 추가하지 않는다.
3. 범주 row의 960px 계약과 보조 제목 크기를 맞춘다.
4. 근거 선반에서 다음 표지 일부가 보이게 한다.
5. 테마 전체 설정과 현재 단일 범주 아코디언은 우선 유지한다.

실제 표지·사전 레이블·정성 값·장르 비보정·분석 막대의 독립성·저장 버튼 없는 즉시 반영·`group` URL·로컬 추천 엔진·런타임 LLM 없음은 유지해야 한다. 계산을 바꾸기보다 정보의 범위와 배치를 정돈하는 작업이 적절하다.

## 검증 한계

- 이 조사에서는 Taste 제품 코드와 사용자 보정값을 바꾸지 않았다. 테스트·typecheck·build도 실행하지 않았다.
- 최초 reveal, normal 코칭, 보정 저장·실패·스낵바, 전체 키보드 순회, reduced motion, 실제 VoiceOver/NVDA는 이번 실행에서 검증하지 않았다.
- 렌더링과 DOM은 구조·가림·문구·접근 가능한 링크 이름의 근거다. 실제 낭독이나 저장 영속성을 대체하지 않는다.
- 전달받은 리뷰의 원래 프로필을 복원하지 않았으므로 해당 프로필의 특정 왼쪽 축 잘림은 미해결 검증 항목이다.
- 캡처는 로컬 개발 화면의 증거이며 배포 증거가 아니다. 원본 9개와 `bottom-metrics.json`은 `.tmp/taste-review-20260912/`에 보존했다.
